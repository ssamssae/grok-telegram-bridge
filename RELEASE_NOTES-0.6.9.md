# 0.6.9 — doctor, and a copy of a service file that setup did not write

- `python3 bridge_setup.py doctor` checks an install at any time and changes nothing. It prints one line per check, marked `[ok]`, `[warn]`, or `[fail]` with a short reason, ends with `doctor complete: N failure(s), M warning(s)`, and exits with 1 when any check fails. It checks that `bridge.env` exists and only your user can open it, and that the chat id is set and is not the example value. It checks that the token file exists, is private, and holds a token; it never prints the token. It finds the `grok` CLI. In the TUI lane it checks tmux, the bridge's tmux session, and the Grok in the bridge pane. A missing session is a failure, because messages from your phone get an error; with `GRB_TUI_FALLBACK_HEADLESS=1` it is a warning. It checks the background service: the launchd agent is loaded on macOS, and the `systemd --user` unit is active on Linux.
- The doctor asks Telegram once (`getMe`) whether it accepts the token. A refused token is a failure; no answer at all is only a warning. `--offline` skips that call.
- On Linux the doctor also checks linger. With `Linger=no`, the service stops when you log out, so the doctor warns and prints the command that turns linger on (`sudo loginctl enable-linger <user>`). It does not run that command.
- The doctor repeats setup's warning about a Grok CLI on a terminal other than the bridge pane, because your phone cannot see that session. Use `grok-tg` instead.
- Setup now ends with `Check the bridge again any time: python3 bridge_setup.py doctor`.
- Setup keeps a copy of a service file that it did not write before it replaces that file. The systemd unit and the launchd plist that setup writes now carry a marker line. When a file with the same name exists without that line, setup saves a timestamped copy next to `bridge.env`, warns, and then replaces the file. An interactive setup asks first; answer `n` and setup leaves that file and the service alone. A unit or plist written by 0.6.8 has no marker yet, so the first setup run after the update keeps one copy of it.
- `setup --dry-run` now shows the service file path and lists the files already there that setup would write over, with what happens to each.

Validation: unit coverage for the doctor (a healthy install, a missing `bridge.env` with exit code 1, files that other users can open, a refused token and no answer from Telegram, `--offline` with no network call, a missing or example chat id, an empty or missing token file, linger off and on with the command never run, a `systemd --user` service that is inactive, not installed, or unavailable, a launchd agent that is loaded, not loaded, or not installed, the TUI lane without tmux or without its session with and without the headless fallback, the headless lane, a missing `grok` CLI, Grok in the bridge pane and on another terminal, the parser, and Telegram's refusal body) and for the service-file copy (a foreign unit or plist copied next to `bridge.env` and replaced, a file that setup wrote replaced without a copy, the interactive question answered `n` and yes, and the dry-run list); 45 setup tests, also run on Python 3.9; mutation probes on the linger check, the outside-session warning, the doctor's exit code, and the service-file copy; the doctor run for real in a throwaway home with a disposable tmux server; the public export with its undefined-global and vocabulary gates; private-data and token scans compared against 0.6.8; release-notes lint; and the public suite (92 tests, 5 other-engine skips, also run on Python 3.9). A source bundle is included.

This is a GitHub release. It does not upload to PyPI, restart an installed bridge, or change an existing config. The bridge itself did not change, so a running bridge needs no restart. To use the doctor, update your checkout and run `python3 bridge_setup.py doctor`.
