# 0.6.8 — One-command setup like the author, and Stop for terminal turns

- One-command setup. `python3 bridge_setup.py setup` first asks `Use the author's setup (recommended)? [Y/n]`; Enter means yes, and `--like-author` skips the question. Setup reads the bot token at a hidden prompt or reuses the saved token file, detects your chat id when you send `/start`, and writes `token.json` (mode 600) and `bridge.env`. It backs up an existing `bridge.env` first and keeps its other settings. The author's setup writes `GRB_CHAT_LANE=tui`, `GRB_TUI_MIRROR_LOCAL=1`, `GRB_TUI_FALLBACK_HEADLESS=0`, `GRB_STOP_BUTTON=1`, `GRB_SEND_NOW_BUTTON=1` and `GRB_QUESTION_PIN=1`, starts Grok in the tmux session `grok` on the socket `grok` through `grok-tui-session-start.sh`, installs a background service (launchd on macOS, `systemd --user` on Linux), and sends a test message. Answering `n` keeps the public defaults: the headless lane, with nothing mirrored. The helper uses only the Python standard library.
- `grok-tg`. Setup links `~/.local/bin/grok-tg` to the `grok-tg` script in the repository. The command reads the tmux socket and session from `bridge.env`, starts the session first when it is missing, and attaches this terminal. It never detaches another terminal, and setup never replaces a different file at that path.
- Self-check. The author's setup ends with three checks: bot to phone; phone to terminal to phone (up to 60 seconds for your message and its answer); and terminal to phone (setup types one short probe into the Grok session and waits up to 90 seconds for its phone card). Each result, with the reason when a check times out, goes to the terminal and to your chat.
- Setup warns when a Grok CLI process runs on a terminal other than the bridge pane, because that session is not connected to your phone.
- `setup --dry-run` prints the files, switches, session, and service that setup would write or start. It writes, starts, and sends nothing.
- Stop for terminal turns. With `GRB_TUI_MIRROR_LOCAL=1`, a turn that you start in the tmux session now gets the same Stop button on its phone progress card. The button belongs to that one turn. It goes away when the turn ends, when the card closes, or when the next request starts, and a press after the turn ended sends no key. A phone request's card takes the button over, and a terminal card whose turn has ended never takes it back. A turn that you cancel with Ctrl+C in the terminal closes its card as interrupted.
- Fix: in 0.6.7 a text line from the bridge's local input (its own terminal, or the local input pipe) raised `NameError` and never reached Grok. That line reaches Grok again.
- Fix: `grok-tui-session-start.sh` called two shell functions that the package did not define, so it looked for the saved Grok session under `/sessions/…` instead of `~/.grok/sessions/…`. Whenever the tmux session had to be started again, for example after a reboot, it opened a new Grok conversation instead of resuming the saved one, and `GRB_GROK_HOME` did not reach the Grok session. The script now applies the same Grok home rule as the bridge: `GRB_GROK_HOME`, then `GROK_HOME`, then `~/.grok`.

A source bundle is included.

This is a GitHub release. It does not upload to PyPI, restart an installed bridge, or change an existing config. To adopt the setup, update your checkout and run `python3 bridge_setup.py setup`. To get the terminal-turn Stop button, restart only the bridge; keep the Grok session and the state directory.
